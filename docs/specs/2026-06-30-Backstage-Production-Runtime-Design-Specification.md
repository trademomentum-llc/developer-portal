## 1. Overview

This document describes the design for running Backstage in a production-like configuration against a PostgreSQL database deployed in the k3d-openchoreo cluster. The Backstage process itself continues to run on the host for this increment; containerizing it is deferred to a future milestone.

---

## 2. High-Level Architecture

```
+----------------------------------+
| Host (macOS)                     |
|  Backstage backend + frontend    |
|  NODE_ENV=production             |
|  app-config.production.yaml      |
+----------------------------------+
            |
            | PostgreSQL
            v
+----------------------------------+
| k3d-openchoreo cluster           |
|  namespace: backstage            |
|  PostgreSQL StatefulSet          |
|  NodePort Service (5432)         |
+----------------------------------+
```

---

## 3. Components

### 3.1 OpenTofu Module: `iac/modules/postgres/`

- Namespace `backstage`.
- Random PostgreSQL password generated by Terraform.
- Kubernetes Secret `postgres-backstage` storing the password.
- PostgreSQL Helm release using the Bitnami chart.
- A NodePort Service exposing PostgreSQL on a host-mapped port.

### 3.2 Database Initialization

A Kubernetes Job or init container creates the `backstage` database and `backstage` user. The Bitnami chart supports creating databases/users via `auth.database`, `auth.username`, `auth.password` values, so we use that mechanism.

### 3.3 Production Startup Script

`scripts/start-backstage-production.sh`:

1. Reads the PostgreSQL NodePort and password from the cluster.
2. Exports the env vars referenced by `app-config.production.yaml`:
   - `BACKEND_SECRET` (generated if missing).
   - `POSTGRES_HOST=127.0.0.1`.
   - `POSTGRES_PORT=<nodeport>`.
   - `POSTGRES_USER=backstage`.
   - `POSTGRES_PASSWORD=<from secret>`.
   - `POSTGRES_DATABASE=backstage`.
   - `GITEA_OAUTH_CLIENT_ID`/`SECRET` from existing files.
   - `GITEA_HOSTNAME=localhost:3333`.
   - `APP_BASE_URL`/`BACKEND_BASE_URL`.
3. Runs `yarn build` if the production bundle is missing.
4. Starts the backend with `yarn start --config app-config.yaml --config app-config.production.yaml`.

### 3.4 Smoke Test

`scripts/smoke-backstage-production.sh`:

- Waits for the production backend to respond.
- Verifies `/` returns 200.
- Verifies guest sign-in is rejected (or not offered).

---

## 4. Security Considerations

- PostgreSQL password is generated by Terraform and stored only in a Kubernetes Secret and exported into the shell at startup time.
- Backend auth secret is generated and stored under `~/.rational-reserve/backstage-backend-secret`.
- Guest provider is disabled in production config.

---

## 5. Testing Strategy

- Run `scripts/install-backstage-production.sh`.
- Run `scripts/start-backstage-production.sh` in the background.
- Run `scripts/smoke-backstage-production.sh`.
- Confirm `scripts/smoke-all.sh` still passes (the production stack is independent of dev mode).

---

## 6. Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| PostgreSQL consumes too much memory | Pin small resource requests and a single replica. |
| Host cannot reach PostgreSQL NodePort | Use `127.0.0.1:<nodeport>`; k3d maps NodePorts to the host. |
| Production startup conflicts with dev server | Use different ports (backend 7009, app 3002) or ensure dev server is stopped first. |
| Gitea OAuth callback mismatch | Use `localhost:7009` callback configured by `setup-gitea-oauth.sh` or a separate OAuth app. |

---

## 7. Acceptance Criteria

- PostgreSQL is reachable from the host.
- Backstage starts in production mode and responds to requests.
- Guest sign-in is not available.
